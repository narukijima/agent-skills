# Validation gates — Level達成の判定

「簡単そう」という主観で完了判定しない。各gateを `pass / fail / not-applicable / blocked` で記録し、`pass` と `fail` には証拠(該当箇所の列挙、数え方、判定理由)を残す。未実行のgateをpass扱いしない。readability scoreは補助信号として記録してよいが、単独でpass判定しない(`levels.md` 根拠参照)。

判定の基準は、指定Levelの認知制約profile(`levels.md`)と対象媒体の適用ルール(`media-rules.md`)である。

検証前に、媒体、Level、Audienceについて分かっていること、目的、保持必須の事実・主張・条件を固定する。Level profileの概念数・推論段数は運用heuristicなので、境界値だけで機械的にpassさせず、受け手の既有知識と情報間の相互作用も判定理由へ含める。

## 理解可能性gates(指定Levelに対して)

- G1 前提知識: 本文・画面が提供しない前提知識を列挙し、各項目がC1の範囲内か判定する。
- G2 専門語: 未説明のまま使われた専門語を列挙する。Levelが未定義使用を許すterm以外は、初出での接地(定義、具体例、対比)があるか。
- G3 抽象度: 具体例に接地されていない一般化・原理を列挙し、C4の範囲内か判定する。
- G4 推論段数: 最も難しい箇所(段落・画面・シーン)で受け手が補う推論stepを数え、C5の範囲内か判定する。
- G5 情報量: 最も密な情報単位の新規概念数を数え、C6の範囲内か判定する。
- G6 文脈依存: 離れた位置の情報保持を要求する構造(指示語、前方参照、凡例往復、巻き戻し前提)を列挙し、C9の範囲内か判定する。
- G7 媒体適合: `media-rules.md` の当該媒体の制約(C10視覚的即時理解性、C11操作・判断負荷を含む)を満たすか判定する。

## 忠実性gates(元の内容に対して)

- G8 正確性: 元出力または保持必須のsource / briefと比較し、事実、数値、条件、限定、重要なnuanceが失われたり歪んだりしていないか。差分を列挙し、それぞれが許容された変更か劣化かを判定する。
- G9 非幼児化: 大人向けアウトプットへchildish register(幼児語、過剰な感嘆、不要な擬人化)を導入していないか。求められるトーンが維持されているか。
- G10 深さ維持: 難しい内容の削除によって平易化していないか。source / briefでカバーすべき主張・概念が単純化後も残っているか。

## 検証強度

- `structural-pass`: G1〜G10のapplicable gateがpassした状態。指定profileに対する構造適合を示すが、実Audienceの理解を証明しない。
- `audience-verified`: structural-passに加え、想定Audienceを代表する参加者でparaphrase test、task-based usability test等を行い、重要な意味・判断・操作が理解された証拠がある状態。対象、方法、sample、失敗と修正を記録する。

実Audienceのtestをしていない場合、「誰でも理解できる」「12歳なら理解できる」と断定しない。高riskな安全情報、医療・法務・金融、同意取得、重要な公共手続では、可能な限りaudience-verifiedを完了条件にする。検証の実施権限や参加者がなければblockedとして分離し、structural-passまでを報告する。

## 完了判定

- すべてのapplicable gateがpassした場合のみ成功とする。
- 理解可能性(G1〜G7)と忠実性(G8〜G10)が衝突して解消できない場合は忠実性を優先し、衝突をfailとして報告する(SKILL.md出力契約)。
- 元の内容へアクセスできない等で判定不能なgateはblockedとし、passにしない。
- 修正した場合は、修正箇所についてfailしたgateを再実行する。
- 結果にはgateごとのstatusと証拠、総合判定、検証強度を含める。
